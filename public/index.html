Connection Setup Guide

Follow these 7 steps to connect Google Antigravity to OmniMCP.

1
Build OmniMCP Gateway
Compile TypeScript source files into the dist/ directory:
npm run build
2
Configure Environment (.env)
Set OMNIMCP_AGENT_TOKEN and downstream credentials in your repository's .env file. STDIO connections use local process boundary isolation, while HTTP/SSE clients use this token.
3
Generate Configuration Snippet
Click Copy Snippet or Download JSON above. The snippet uses forward slashes (/) for safe Windows path resolution.
4
Add to Antigravity Configuration
Merge the omnimcp entry under mcpServers in ~/.gemini/antigravity/mcp_config.json.
5
Restart or Reload Antigravity
Reload your IDE or restart the agent so it launches OmniMCP over STDIO process boundaries.
6
Verify Upstream Connection
Confirm that Antigravity recognizes OmniMCP and lists its 10 top-level routing tools without errors.
7
Discover & Execute Downstream Tools
Antigravity can now search child tools dynamically via search_tools and execute them through governed approval workflows.

Troubleshooting Common Setup Issues

Fast diagnostics for host connection and handshake errors.

Invalid Node.js Executable Path

Verify that Node.js executable exists at the configured path and is executable from standard terminal sessions. Run node -v to verify compatibility (Node.js v20+ recommended).

Missing dist/index.js

The TypeScript build output must be present. Run npm run build inside the OmniMCP directory before starting Antigravity.

Invalid Agent Authentication Token (HTTP/SSE)

If HTTP/SSE requests return 401 Unauthorized or 403 Forbidden, confirm that the Bearer token matches OMNIMCP_AGENT_TOKEN in your gateway's .env. STDIO transport uses process isolation and does not require a token in mcp_config.json.

MCP Protocol Handshake Failure

OmniMCP enforces strict STDIO cleanliness: all diagnostic logs route strictly to stderr, keeping stdout reserved for valid JSON-RPC frames. Do not print unformatted strings to console.log.
